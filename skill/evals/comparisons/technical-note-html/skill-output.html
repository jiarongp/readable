Constraint scoring note

title: Constraint scoring notestatus: draft

This note describes how a candidate gets a feasibility score, how the implementation scores a batch of candidates at once, and what the score does and does not tell you. The batch size is 32; the reason for that choice is not recorded.

The evaluation cases accompany this note. The probability calculation is in Feasibility.

Three terms carry the whole note.

Candidate
One option under consideration, written \(x\). The note does not say what the coordinates of \(x\) are; in the implementation a candidate is one row of an array.
Constraint
A condition a candidate must satisfy. Constraint \(j\) is a function \(g_j\), and the candidate satisfies it when \(g_j(x) \le 0\). Writing every constraint in this “at most zero” form is a convention: a hypothetical limit such as “mass at most 5 kg” becomes \(\mathrm{mass}(x) - 5 \le 0\).
Satisfaction probability
\(P(g_j(x) \le 0 \mid x)\): the probability that constraint \(j\) holds for candidate \(x\). The note treats these probabilities as given inputs and does not say how they are computed.

A candidate is feasible when it satisfies all of the constraints at once. The score in this note is an estimate of the probability that it does.

Feasibility

The feasibility score multiplies the satisfaction probabilities of all the constraints. Multiplying is the rule for combining independent events. As a hypothetical instance, if a candidate satisfies constraint 1 with probability 0.9 and constraint 2 with probability 0.8, and the two outcomes have nothing to do with each other, then it satisfies both with probability \(0.9 \times 0.8 = 0.72\).

Under the assumption that the constraint events are independent conditional on the candidate \(x\), the probability of feasibility is

$$ P(\mathrm{feasible}\mid x)=\prod_{j=1}^{m}P(g_j(x)\leq 0\mid x) $$

Here \(m\) is the number of constraints. \(g_j(x) \le 0\) means that constraint \(j\) is satisfied at \(x\), so each factor is the probability of satisfying one constraint for this candidate. The product runs over all \(m\) constraints.

With \(m = 3\) and hypothetical probabilities 0.9, 0.8 and 0.7, the score is \(0.9 \times 0.8 \times 0.7 = 0.504\). Each factor is below 1, so every extra constraint lowers the score. The figure shows how fast that happens.

The independence assumption matters. Independent conditional on \(x\) means that, for a given candidate, knowing one constraint is satisfied tells you nothing about whether another is. If the constraint events are dependent, the product is no longer a valid calculation of feasibility.

A hypothetical case shows the size of the error. Suppose constraints 1 and 2 react to the same quantity, so that whenever constraint 1 holds, constraint 2 holds too. With probabilities 0.8 and 0.9, the true probability of satisfying both is 0.8, because satisfying constraint 1 already guarantees constraint 2. The product gives \(0.8 \times 0.9 = 0.72\), which is too low. Dependence in the opposite direction, where one constraint holding makes another less likely, makes the product too high.

Batch operation

The implementation scores all 32 candidates in one call. Its input, probabilities, is an array with shape (32, 3): 32 rows because there are 32 candidates, and 3 columns because there are 3 constraints. The entry in row i, column j is the satisfaction probability of constraint j for candidate i.

prod(axis=1) multiplies the entries along axis 1, which runs across the columns of each row. Each row therefore collapses to one number, its feasibility score, and the result is a vector with shape (32,), one score per candidate in the same order as the rows.

def feasibility_score(probabilities):
    return probabilities.prod(axis=1)

The function multiplies each row without checking whether the independence assumption from Feasibility is justified, and this note does not establish that it is. The result is a score under the stated assumption, not a guarantee that the selected candidate will satisfy the constraints. A score of 0.504 says that, if the assumption holds, the candidate is roughly as likely as not to be feasible; whether it actually is feasible is not something the score settles.
